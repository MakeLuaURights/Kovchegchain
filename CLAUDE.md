# Ковчег (Kovcheg) — блокчейн с нуля, монета KVG

Свой блокчейн, написанный с нуля. **Не форк** — весь код свой, сторонние
библиотеки только для инфраструктуры (хранилище bbolt).

Позже к сети подключатся Telegram-бот, мини-апка-кошелёк и сайт-обозреватель.

## Среда

- Разработка и запуск: **Android, Termux, без root**.
- Язык **Go**, сборка **без CGO** (`CGO_ENABLED=0`). Никаких зависимостей на C.
- Хранилище: `go.etcd.io/bbolt` (чистый Go). Версия закреплена на v1.4.x —
  v1.5+ требует Go 1.25, а в Termux версия Go может отставать.
- `go.mod`: `go 1.23`. Не поднимать без необходимости.

## Этапы

1. **Ядро и один узел** — готов
2. **Полное HTTP API узла** ← *текущий этап, готов*
3. Telegram-бот
4. Мини-апка-кошелёк
5. Обозреватель блоков
6. Токены и NFT
7. Несколько узлов, Proof of Stake

## Правило работы

**Делать только текущий этап.** После его завершения остановиться и кратко написать:
что сделано, как запустить, что проверить. Следующий этап начинать только по
команде владельца проекта.

## Устройство

```
cmd/kovcheg/        CLI: wallet, genesis, node, balance, send, history, tx, block, status
internal/core/      типы и правила: адрес, сумма, транзакция, блок, состояние, генезис
                    testdata/sign_vectors.json — тестовые векторы подписи для клиентов
internal/storage/   bbolt: блоки, индексы, аккаунты, история адресов, счётчики;
                    блок + состояние + индексы пишутся одной транзакцией базы
internal/chain/     узел: мемпул, сборка блока раз в 5 с, проверка блока, подписка на блоки
internal/wallet/    ключи ed25519, файл wallet.json
internal/api/       HTTP API v1 (+ адреса этапа 1), поток событий SSE, CORS,
                    ограничение частоты; клиент для CLI
docs/api.md         описание API для бота, мини-апки и обозревателя
```

### API (этап 2)

- Все новые адреса — под `/v1/`. Старые `/info`, `/balance`, `/tx`, `/block`
  не удалять: менять их можно только добавляя поля.
- Ошибка = `{"error": текст, "code": код}`; коды — в docs/api.md. Новый вид ошибки —
  новый код в `errorCode` и в таблице docs/api.md.
- Списки — от новых к старым, курсор `?before=`, `?limit=` до 100, пустой список `[]`.
- Поток событий `/v1/events` (SSE): `id` = номер блока, догон через `Last-Event-ID`/`?since=`.
  Медленный подписчик отключается (буфер 64 блока) и переподключается сам.
- Запросы, которые живут дольше `WriteTimeout` (SSE, `?wait=true`),
  продлевают дедлайн через `http.ResponseController`.
- Индексы (`txs`, `addrtxs`, счётчики) выводятся из блоков. При изменении их формата —
  поднять `indexVersion` в storage: узел перестроит их сам при запуске.
- При изменении `SigningBytes` — пересоздать векторы:
  `go test ./internal/core -run TestSigningVectors -update`.

### Правила сети

- **Ключи** ed25519. **Адрес** = `"kvg"` + hex(первые 20 байт SHA-256(pubkey)),
  43 символа, hex только строчными.
- **Суммы** — только целые `uint64` в нано-KVG. `1 KVG = 10^9 нано-KVG`.
  Плавающая точка запрещена везде. В JSON все `uint64` пишутся **строками**
  (чтобы JS-клиенты не теряли точность).
- **Аккаунт**: `balance`, `nonce`. `nonce` = число принятых исходящих транзакций;
  новая транзакция обязана иметь `nonce == account.nonce`.
- **Транзакция**: `chain_id, from, to, amount, fee, nonce, pub_key, signature`.
  Подписываются канонические байты (`Tx.SigningBytes`: префикс `KVG-TX-v1`,
  поля с префиксами длины / big-endian). Хэш tx = SHA-256 этих байт.
  `pub_key` обязателен — адрес это хэш, по нему ключ не восстановить.
  Проверки: сеть, формат адресов, `amount > 0`, `fee >= min_fee`, переполнение,
  `from == address(pub_key)`, подпись, nonce, баланс `>= amount + fee`.
- **Комиссии** идут производителю блока (`Block.Producer`, флаг `-producer`).
- **Блок**: `height, time, prev_hash, tx_root, producer, txs, hash`.
  `hash` = SHA-256 заголовка (`KVG-BLOCK-v1`); транзакции входят через `tx_root`
  (дерево Меркла). Время блока не меньше времени предыдущего.
- **Генезис** (`genesis.json`): блок 0 без транзакций, `prev_hash` = SHA-256
  канонической записи генезиса. Суммы в genesis.json — в KVG строкой.
  По умолчанию 1 000 000 000 KVG на адрес создателя. Узел отказывается
  стартовать, если база создана с другим генезисом.
- **Узел**: один, без консенсуса. Каждые 5 с собирает блок из мемпула
  (пустые блоки по умолчанию не создаются, флаг `-empty-blocks`).
  Мемпул проверяет транзакции против состояния *с учётом* ожидающих
  транзакций (двойная трата отсекается уже на входе). Мемпул в памяти —
  при перезапуске узла неподтверждённые транзакции теряются.

### Соглашения

- Сообщения об ошибках и комментарии — на русском.
- Изменение формата `SigningBytes`, `ComputeHash` или генезиса ломает
  совместимость с уже созданными базами — только с новой версией префикса.
- Перед коммитом: `gofmt -l .` пусто, `CGO_ENABLED=0 go vet ./...`,
  `CGO_ENABLED=0 go test ./...`, сборка `GOOS=android GOARCH=arm64 CGO_ENABLED=0 go build ./cmd/kovcheg`.
- Владелец проекта тестирует только финальную версию в Termux: всё, что можно
  проверить здесь (сборка, тесты, живой запуск узла и команд), проверять самому.
